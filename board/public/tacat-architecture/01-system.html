tacat architecture · 01 of a series

System overview

tacat is a knowledge graph of three PLP-dependent transaminase reactions: an OWL ontology, reasoned over at build time, served through a SPARQL 1.1 endpoint. This diagram shows the components and the direction data moves between them.

The architecture is organised around one decision, and it is the horizontal band in the middle of the diagram: reasoning happens when the image is built, never when a request is served. Everything above that line needs a JVM and runs once; everything below it loads a finished artefact and needs no reasoner at all.

Reading the diagram

The dashed line is the whole design

Above it, builder.py assembles the T-Box and A-Box, runs HermiT, and writes data/reactions.ttl with the inferred types already materialised. Below it, nothing reasons. The container's builder stage installs a JVM; the runtime stage installs no Java at all and copies only the finished graph.

The consequence worth stating out loud: the served endpoint answers ?r a tacat:TransaminationReaction — an inferred type — from plain SPARQL with no reasoner in the request path. And if reasoning fails, the image does not build.

The line terminates in artefacts.py because that is the seam expressed as code rather than as a diagram. It resolves one agreed location for the graph — $TACAT_DATA_DIR in the container, ./data in a checkout — so neither side hard-codes a path, and it deliberately imports nothing from ontology/. That omission is the load-bearing part: it is what stops the serving process from pulling in Owlready2, and therefore what makes "no JVM at run time" a property of the code rather than of the Dockerfile alone.

What schema.py actually contains — the n-ary participation pattern, the defined class whose four conjuncts produce that inferred type, and the negative control that must not match — is sheet 02.

Two contracts, drawn in violet

GraphRepository and QueryPolicy are the only stated interfaces. They exist for legibility rather than portability — the honest claim is that they make the architecture readable, not that a different store could be dropped in unchanged. GraphRepository deliberately exposes an rdflib escape hatch, because pySHACL cannot be handed a Protocol.

QueryPolicy imports no web framework and raises a domain error the HTTP layer translates, so the read-only rules are testable without a client. A test asserts the absence of that import.

Arrows point the way data moves, not the way modules import

reference_data.py is the single source of curated truth and has no dependencies of its own; three separate modules read it. namespaces.py holds only constants — including SOURCE_REPOSITORY, which is written into the graph as a provenance target rather than being documentation.

What the diagram does not show. The CI pipeline (four stages: quality → verify → build → smoke) and the two-stage Dockerfile both wrap this picture rather than appear in it. They are the subject of sheet 03.

Components

ModuleResponsibility
reference_data.pyVerified ChEBI, Rhea, EC and UniProt identifiers as frozen dataclasses. The one source of curated truth; its SHA-256 is recorded in provenance.
ontology/namespaces.pyNamespace constants. SOURCE_REPOSITORY becomes a prov:wasRevisionOf target in the graph.
ontology/schema.pyThe T-Box — classes, properties, and the defined class TransaminationReaction. One function, because the Owlready2 DSL requires lexical co-location.
ontology/population.pyThe A-Box — reaction, participant and entity individuals built from the reference data.
ontology/linking.pyTypes every minted node as an instance of the external class it reuses. The fix for the defect that made the predecessor unjoinable.
ontology/provenance.pyPROV envelope: software version, reference-data checksum, commit SHA. Deliberately no wall-clock timestamp — a test fails if one is added.
ontology/builder.pyOrchestration only: schema → populate → HermiT → flatten the world → link → provenance.
ontology/inference.pyReports what was asserted versus what the reasoner derived. Backs the tacat infer command and the CI inference gate.
ontology/build.pyStable entry point. Re-exports the build surface so callers depend on one name rather than on the internal split.
store/repository.pyGraphRepository — the contract between the service and the graph it serves.
store/memory.pyIn-process implementation; loads the Turtle artefact, falling back to an in-process build if it is missing.
store/statistics.pyGraph statistics for the landing page, counted by SPARQL against the contract rather than by reaching into rdflib.
api/policy.pyQueryPolicy — query-form whitelist and result cap, via a lexical scanner rather than a regex, because # is legal inside an IRI.
api/negotiation.pySPARQL 1.1 result serialisation and content negotiation.
api/examples.pyThe queries the landing page advertises. Every one is executed by the test suite — an advertised query that does not parse is a defect a green suite would otherwise hide.
api/app.pyFastAPI wiring. Queries run in a threadpool so one expensive request cannot block /health.
queries/competency.pyCompetency questions as the executable specification — CQ01–CQ04 quoted from NFDI4Cat's own set, CQ10–CQ11 the identifier oracles.
queries/federated.pyThe live Rhea/UniProt join, behind tacat federate. Refused in the HTTP request path.
validation.pypySHACL over data/shapes.ttl, exposed at GET /validation.
artefacts.pyThe build-time / run-time seam. Resolves the artefact directory ($TACAT_DATA_DIR, else ./data) for both sides, and imports nothing from ontology/ so the runtime never pulls in Owlready2.
tacat_logger.pyget_logger(name). A dedicated logging module, never bare print — house style, and it is what makes the build's decisions observable in CI.
cli.pybuild · infer · serve · federate · questions · query.
