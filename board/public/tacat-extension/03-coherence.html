Chapter 3

Three sources or none

Every curated fact in this repository was verified against a primary database by a human. That work is genuine and it does not re-run. There is a theorem about how many independent sources a claim needs before it survives one of them being wrong — the answer is three, not two — and it converts provenance from a record into a check.

★★ high value 11 min PLAN §3 · human verification cheap to check, expensive to skip
Provenance. This chapter rests on unpublished single-author work (Semantic Causal Propagation, §7). It has not been peer-reviewed. The coherence result below is a claim about robustness under source failure, not about truth — a coherent triangle of sources can be uniformly wrong, and the chapter says so in §5. Read the theorem as setting a floor on how little evidence is enough, never a ceiling on how much is needed.

1. The problem

GAPS_2.md G10 makes an observation about the human verification behind reference_data.py that is easy to read past:

GAPS_2.md §G10

"What defends against it today is human verification — every identifier checked individually against its primary database, recorded in PLAN.md §3, with the three counterintuitive cases documented inline. That work was done and is genuine. It is not a gate: it does not re-run, and it cannot fail a pipeline."

There is a second problem underneath it. Even where verification was done, the record does not say how many independent sources agreed. Nine ChEBI identifiers were checked against ChEBI. That is one source checked once — and a source checked against itself is exactly the self-consistent single cluster from Chapter 2.

Where this already nearly went wrong

v0's identifiers came from one systematic method: ChEBI resolved via KEGG's conv/chebi cross-reference. One source, one method, uniformly applied — and uniformly wrong, returning the neutral parent every time. A second independent source (Rhea's own participant list, which uses microspecies exclusively) would have disagreed on every single entity at the first comparison.

2. Why two is not enough

The calculus models corroboration as a support graph: a directed edge from one source to another when the first reinforces the second's contribution to the same claim. The question is what shape that graph must have for the claim to survive losing any one source.

Thm · Coherence requires three Semantic Causal Propagation, Thm 7.9

(i) Necessity. If a set of sources grounds a claim and remains grounding after the failure of any single source, the shortest support cycle compatible with that robustness has length ≥ 3.

(ii) Sufficiency. Three sources mutually supporting one another form a strongly connected triangle; the claim survives removal of any single member.

The exclusions are argued individually, and they are the interesting part:

ShapeWhy it failsConcrete form
Chain
A → B → C		 The terminal source is supported by nothing. Remove it and each predecessor collapses in turn. "KEGG says so, and KEGG cites ChEBI." Remove KEGG's mapping and nothing remains.
1-cycle
A → A		 Self-support. Vacuous. A label checked against the row that generated it — G10 exactly.
2-cycle
A ⇄ B		 Mutual definition with no independent check. Remove either and one unsupported source is left. Two cannot outvote their own disagreement. ChEBI and a database that imports ChEBI. They agree because they are the same source twice.
Triangle
A ⇄ B ⇄ C ⇄ A		 Each is supported by the other two. Removal leaves a supported pair. ChEBI · Rhea · UniProt — which this project already federates against.

3. The part that makes it cheap

Cor · Coherence is ordinally decidable Semantic Causal Propagation, Cor. 7.10

Whether a set of sources is coherent is decidable from the signs of pairwise support alone — whether each pair agrees or conflicts — with no access to any numerical confidence, weight or score.

Why this matters for an implementation

You never have to invent a confidence number. No "ChEBI is 0.9 reliable, KEGG is 0.7". The check is: does source X's answer agree with source Y's answer, yes or no — build the graph of agreements, look for a triangle. That is a handful of set comparisons and a cycle search over a graph with three or four nodes. It is trivially implementable and there is nothing to tune, which also means nothing to argue about in review.

4. What this proposes building

4.1 Provenance that records independence, not just origin

data/dataset.ttl carries a PROV envelope, and GAPS_0.md G3 already criticised it for being static — "nothing records which build produced this graph". The coherence result adds a second criticism: nothing records how many independent sources back each fact, so the envelope cannot distinguish a fact confirmed three ways from one asserted once.

4.2 A SHACL shape that enforces it

This is where it stops being documentation. The project already validates with SHACL under --metashacl; a coherence requirement is expressible as an ordinary cardinality constraint, which means an under-supported fact fails the build rather than being noted in a README.

It fits the existing discipline exactly

RATIONALE.md §4 lists the project's response to silent failure: "make failure loud" — a reasoning gate that asserts the inference fired, --metashacl so a malformed shape fails rather than constraining nothing, a negative control that would classify if the definition were keyed on the wrong thing. A coherence minimum is the same move applied to provenance: it converts "we checked carefully" from a claim in a document into a condition the build enforces.

5. What this does not fix

Be able to say this out loud
  • Three agreeing sources can be uniformly wrong. The theorem is about robustness to one source failing, not about truth. If ChEBI, Rhea and UniProt all inherit an error from a common upstream curation, the triangle is coherent and wrong. Coherence is a floor on evidence, never a certificate.
  • "Independent" is doing enormous work and is not formally defined here. Rhea cites ChEBI identifiers directly — so are they independent? For formula and charge, arguably not; for which species participates in RHEA:19453, yes, because that is Rhea's own curation. The honest implementation records what each source agrees on rather than claiming blanket independence, which is why tacat:agreesOn is a field above.
  • A sh:minCount 3 could be satisfied by three cheap sources. The constraint counts, and counting is gameable. It raises the floor; it does not replace judgement about which authorities are worth consulting.
  • For a nine-entity demo this is arguably over-engineering, and that should be said plainly rather than defended. Its value is at curation scale — hundreds of entities where nobody can check each one by hand. The demo would carry it as a demonstrated pattern, not as necessary infrastructure.
