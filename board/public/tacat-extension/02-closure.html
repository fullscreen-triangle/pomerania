Chapter 2

Closure, not confidence

"The suite is green" is a stopping rule, and it is the wrong one. There is a strictly stronger criterion — stop when no further check available to you could change the answer — and it is decidable, cheap, and directly applicable to a curation pipeline that must tell a biochemist when a fact is settled.

★★★ strongest transfer 14 min RATIONALE §4 · "everything fails green" this is the one to lead with
Provenance. This chapter rests on unpublished single-author work (Semantic Causal Propagation, §8). It has not been peer-reviewed. The closure criterion below is independent of the recognition/search identity in the same paper — it is provable from the floor and the catalyst algebra alone — so it survives even if that identity is rejected. Stated here because it is the one place where knowing which wall is load-bearing matters.

1. The problem, in this repository's own words

RATIONALE.md §4 names the through-line of the whole submission:

RATIONALE.md §4

"If the exercise has one idea, it is that everything here fails green." Wrong ChEBI microspecies → federated join returns zero rows, no error. Identifier stored as xsd:string → same. Defined class that classifies nothing → passes an OWL consistency check. sh:minCounts typo → constrains nothing, reports no violations.

Every one of those is the same structural fact: a green suite is evidence that the checks you wrote passed, and nothing more. It says nothing about the checks you did not write, and the checks you did not write are exactly where the error is — because if you had thought of the check, you would have thought of the error.

The sharpest instance

RATIONALE.md §4 on v0's balance tests: they were "an original idea nobody asked for, they passed, and they were structurally incapable of detecting the error actually present" — because they read local formula/charge fields and never dereferenced the identifier. The confidence was highest exactly where the error lived. That sentence is a description of a confidence threshold failing, and it is what the closure theorem formalises.

2. Closure

The search calculus models an inquiry as a walk through a graph of claims, where each step is a catalyst — any operation that resolves something: a database query, a file scan, a reasoner run, a human check. Two claims are in the same equivalence class when no test available at the endpoints distinguishes them.

Definition · Closure Semantic Causal Propagation, Def. 8.2

A search is closed when, for every catalyst available but not yet invoked, extending the search by that catalyst cannot add a new equivalence class: every further admissible result terminates in a class already reached.

Thm · Closure is strictly stronger than a threshold Semantic Causal Propagation, Thm 8.3

There exist process graphs and thresholds θ such that a result satisfies the confidence criterion while the search is not closed — a further, uninvoked catalyst reaches a structurally distinct class.

The construction is uncomfortably realistic: two disjoint, internally dense clusters, each reachable by one catalyst. Propagate via the first alone and terminal confidence is maximal, because a claim's alignment to itself is always at the floor. The second catalyst, never invoked, reaches an entirely different answer. High confidence, wrong result, threshold structurally unable to notice.

The one-sentence version

A single source reports high confidence because it is internally self-consistent — which is exactly what a single source always is. Confidence measures agreement within what you consulted. Closure measures whether there is anything left to consult that could disagree.

3. The picture

4. Two ways to finish, and one of them is "decline"

Thm · Convergent closure or honest decline Semantic Causal Propagation, Thm 8.5

Every search over a finite catalyst registry terminates in exactly one of two states: convergent closure — the reachable set stabilises to a single equivalence class, which is the answer; or contested closure — it stabilises with more than one class, and the correct output is decline, reported together with the distinct classes found.

Decline is not failure. It is the outcome that says the sources disagree, and here is where — which for a curation pipeline is often the most valuable thing it can produce, because it localises exactly the fact that needs a human.

Threshold pipeline

Consults ChEBI. Gets an answer. Confidence high. Emits it.

If UniProt would have disagreed, nobody finds out. The disagreement is not recorded as absent — it is simply never generated.

Closure pipeline

Consults ChEBI, UniProt, Rhea. Two agree, one differs. Reachable set has two classes.

Emits decline with both classes and their sources. A curator sees a specific conflict, not a silent choice.

5. What this proposes building

5.1 A closure report beside the test report

The competency-question suite currently answers "did the checks pass?". A closure report answers the different question "is there a check we have not run that could change an answer?" — over the registry of authorities the project already federates against.

Why the last block is the whole argument

That contested result is already documented in this repository — RATIONALE.md §3.2 and IMPLEMENTATION_REPORT.md §4 record that E. coli AlaA carries the same Rhea master as human ALT1 with PhysiologicalDirection=right-to-left. It was found by a human reading UniProt carefully. A closure check generates that finding mechanically, and would have found it without anyone thinking to look — which is the difference between a fact the project knows and a gate the project runs.

5.2 Wiring it to the existing federated layer

This is cheaper than it looks, because the parts exist. queries/federated.py already constructs and runs joins against Rhea and UniProt, with a cache and two network-marked tests. Closure needs three additions on top of that:

PieceWhat it isExists?
Catalyst registryNamed authorities with a fetch function eachPartly — federated.py hard-codes two endpoints
Equivalence testWhen do two answers count as the same class? For a chemical entity: formula + charge. For a reaction: participant ID set.No — this is the design work
Report + exit codeContested → non-zero, artefact writtenNo — but mirrors the existing questions verb

The equivalence test is where the judgement lives, and it should be explicit and small. Two answers are in the same class when the fields the project claims to care about agree — which forces the project to say which fields those are. That is the same discipline as tacat:notCompared in Chapter 1, arrived at from the other direction.

6. What this does not fix

Be able to say this out loud
  • Closure is relative to a registry. Thm 8.5's termination guarantee holds over a fixed, finite set of catalysts. Adding an authority re-opens the question. So "closed" always means "closed over these three sources on this date" — which is exactly why the report must name them, and why it is a dated artefact rather than a boolean.
  • The equivalence test is a modelling choice, not a derivation. The theorem says closure is decidable given a notion of "materially different"; it does not supply one. Choosing formula-plus-charge for a chemical entity is a defensible judgement that could be wrong — stereochemistry is deliberately excluded and that exclusion should be recorded.
  • It adds a failure mode: contested results need a human. A pipeline that can emit decline needs somewhere for decline to go. For a three-reaction demo that is a report; for a real curation flow it is a queue, and the queue is the expensive part. Naming that cost is part of proposing the thing.
