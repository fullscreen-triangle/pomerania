Chapter 7

Chemical identity

“L-glutamate” is not one thing. It is a family of closely related species that differ by where a few hydrogen atoms sit, each with its own identifier, and reaction databases use the members of that family precisely. This chapter is the anatomy of the bug that made the first submission unjoinable — and it is a data-modelling problem, not a chemistry one.

1. Molecules gain and lose hydrogen depending on where they are

Certain parts of a molecule can gain or lose a hydrogen ion — a bare proton, H⁺. Losing one leaves a negative charge behind; gaining one adds a positive charge. Which happens depends on the acidity of the surroundings.

Every such site flips independently, so one compound exists as several forms at once, in a proportion set by the pH. At the pH inside a cell (about 7.4), a given compound is usually dominated by one form — but it is not the form you would draw on a whiteboard.

NameFormulaChargeWhich one this is
L-glutamic acidC5H9NO4 0the neutral form — the textbook drawing
L-glutamate(1−)C5H8NO4 −1the form that actually predominates in a cell

One hydrogen apart. Different formula, different charge, different mass — and, crucially, different identifiers in every chemical database.

The exact analogue in your world

Unicode normalisation. “é” can be one code point (U+00E9) or two (U+0065 U+0301). They render identically, they mean the same character to a human, and s1 === s2 is false. If one system stores NFC and another stores NFD, every lookup silently misses — no exception, no warning, just nothing found.

A microspecies is the chemistry version of a normalisation form. Same compound to a human; a different key to a database.

2. The four relationships you have to keep apart

Two identifiers can be related in several distinct ways, and they behave differently. A pipeline that assumes one uniform rule will corrupt half its data.

RelationshipDiffer byExample from this project
Conjugate acid / base a hydrogen ion, so charge and formula both change L-glutamic acid 16015 ↔ L-glutamate(1−) 29985
Tautomer where a hydrogen sits within the molecule — same formula, same total charge, different structure, interconverting spontaneously L-cysteine 17561 ↔ L-cysteine zwitterion 35235
Zwitterion a form carrying both a positive and a negative site, net charge 0 — not the same as uncharged L-alanine zwitterion 57972
Stereoisomer the same atoms and bonds, mirrored in 3D. Biologically these are different substances L-alanine vs D-alanine — the L- prefix is doing real work

Note the third row especially: a zwitterion has net charge zero and internal charges, so “charge = 0” does not imply “the neutral form”. The formulae differ even when the charges match.

3. The failure, step by step

The first submission’s reference data cited, for each compound, an identifier and a formula and charge. Its stated method:

“Compound identities — ChEBI, resolved via KEGG’s conv/chebi cross-reference.”

KEGG’s mapping returns the neutral parent. The formulae and charges, however, were taken from the physiological microspecies. So every row paired a neutral-form identifier with anionic-form data — systematically, off by exactly one hydrogen per unit of charge, because a systematic method produced it.

Zero rows, HTTP 200, green test suite

That is the whole failure. No exception. No validation error. The README claimed interoperability; the tests were green; the thing the claim promised did not work. As the review put it, the worst failure mode available.

4. Why the tests could not have caught it

This is the part worth taking away, because it generalises well beyond chemistry.

The suite had two kinds of check. Here is the identifier check:

assert c.chebi and c.chebi.isdigit(), f"{c.key} missing ChEBI"

A format check, not a correctness check. "99999999" passes. It confirms the field is populated and shaped like an accession, which tells you nothing about what it points at.

And here is the clever one — mass and charge balance:

def test_reaction_is_mass_balanced(rxn):
    assert sum_formula(rxn.substrates) == sum_formula(rxn.products)

It reads the formula and charge fields. It never dereferences the ChEBI identifier. Because the author used microspecies values consistently, the arithmetic balanced perfectly — so the suite “proved” mass and charge balance on data that did not belong to the identifiers written beside it.

The general principle

A test over locally-consistent data cannot validate an external reference. Internal consistency and external correctness are independent properties, and checking the first gives you confidence about the second that you have not earned.

You have hit this exact shape before: a fixture file that agrees with itself and disagrees with production. A mock whose contract drifted from the real API. A migration test that passes against the test schema. The tests are green because everything they touch was written by the same hand.

A test that would have caught it: assert each ChEBI ID appears in the participant list of the corresponding Rhea reaction — or, offline, pin the expected formula and charge per ChEBI ID from a checked-in fixture derived from ChEBI, rather than hand-entering identifier and data together as one row. Note the structural difference: the check has to cross the boundary the claim crosses.

5. Three traps that are pure string handling

These are recorded inline in reference_data.py, and all three are your territory.

The tautomer that owns the bare name

Resolving the string "L-cysteine" in ChEBI lands on CHEBI:17561 — a tautomer, and not the species these reactions use (CHEBI:35235). The obvious lookup returns the wrong answer confidently.

Rule: never resolve a chemical from a name string. Names are labels; identifiers are keys.

U+2212 versus U+002D

ChEBI writes charge suffixes with the MINUS SIGN U+2212, while the L- stereochemistry prefix is an ordinary ASCII HYPHEN-MINUS U+002D. The same string contains both: 

"L-glutamate(1−)"
#  ^ U+002D HYPHEN-MINUS      ^ U+2212 MINUS SIGN

Scrape one source, load a dump from another, join on the name: silent failure. And a well-meaning “normalise the dashes” pass corrupts the data rather than fixing it, because the character ChEBI uses is U+2212 and matching its own data requires preserving it. The project’s linter config carries a targeted RUF001 ignore for that one file with the reason written down, rather than letting a linter quietly ASCII-fold it.

Display names diverge from database names

ChEBI’s accepted name and the string Rhea prints differ for three of these participants — CHEBI:57972 is L-alanine zwitterion in ChEBI and plain L-alanine in Rhea’s equation. UniProt does the same: it displays friendly names while the cross-references underneath are microspecies. That gap between the display string and the key is precisely what produced the original error.

6. The cofactor has the same problem

PLP from chapter 6 is not exempt. UniProt’s COFACTOR annotation reads: 

COFACTOR: Name=pyridoxal 5'-phosphate; Xref=ChEBI:CHEBI:597326

CHEBI:597326 is the dianion — charge −2 — not CHEBI:18405, the neutral parent that a search for “pyridoxal 5′-phosphate” returns first. Same trap, same shape, in the one molecule the project makes a point of modelling carefully.

Note what balance does and does not prove

It balanced before the fix too. Balance is a property of the numbers, and the numbers were always the microspecies numbers — only the identifiers were wrong. Balance is a genuinely good invariant to test, and it is orthogonal to the question of whether the identifiers point at the right things. Two independent properties; you need a check for each.

Chapter 7 in five lines
  • One compound exists as several microspecies; each has its own identifier and reaction databases use them precisely.
  • Conjugate pairs, tautomers, zwitterions and stereoisomers are four different relationships — no uniform rule covers them.
  • The wrong microspecies gives zero rows, HTTP 200, and a green suite.
  • A test over locally-consistent data cannot validate an external reference. The check must cross the boundary the claim crosses.
  • Never resolve a chemical from a name string; and do not normalise ChEBI’s U+2212 away.
