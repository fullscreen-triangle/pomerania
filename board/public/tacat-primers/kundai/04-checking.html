Checking the data

Two machines run over this graph and they do opposite jobs. Separating them cleanly is one of the fastest ways to show you have worked with this stack.

You already know both halves

Open world is how you read an experiment: no catalase assay means no catalase result, not a negative one.

Closed world is how a sample submission form works: leave the buffer field blank and the sample is rejected. The facility does not reason about what the buffer might have been.

2. The example that shows they are genuinely different

Suppose the ontology says a dataset has at most one licence, and the data asserts two: CC-BY and CC0. Press run.

Same data, same constraint, opposite outcome — and the OWL outcome is worse than useless, because it has silently declared two incompatible licences identical. Neither engine is wrong. Using only one of them leaves a real gap.

3. What SHACL looks like

SHACL is written in RDF itself — the rules for the data are in the same format as the data. A shape targets a class and lists what must hold.

For every ReactionParticipant node —

  • it must be a named node, not anonymous;
  • exactly one participatingEntity, and it must be a link, not text;
  • exactly one coefficient, decimal, greater than zero.
Why the bridge node is what gets guarded

Recall from Chapter 3 that CQ06 works by filtering on the participant's role. A participant missing its role does not error — it drops out of the join and quietly changes the answer. Four participants become three; the query still returns a tidy table.

The shape exists precisely because that failure is invisible.

Two details worth mentioning out loud

Every constraint carries an sh:message. A machine-generated default message tells whoever has to fix the data almost nothing. Writing the message is where the reasoning gets recorded — the coefficient message explains why decimal and not double: stoichiometric coefficients are exact ratios, not measurements, and binary floating point cannot represent ⅓ of an equivalent exactly. Silent rounding inside a balance check is the kind of bug nobody finds.

The validator runs with --metashacl — "also check the shapes file is itself valid SHACL". Without it, sh:minCounts instead of sh:minCount is not an error: it is an unrecognised property, so the constraint silently constrains nothing and every validation passes. Same failure shape, one level up.

4. What a test is, for someone who has not written one

A test is a small piece of code that runs the real code and asserts what the answer should be. If the assertion fails, the build stops.

You already know this

A test is a positive control you run every time. Not because you expect it to fail, but so that when something drifts you find out immediately rather than in a reviewer's comments.

The term for "a test that stops a fixed bug coming back" is a regression test. Every defect found in the review has one.

182tests collected
12negative — deliberately bad data
11competency questions

The twelve negative cases feed the shapes deliberately broken data — a participant with no role, a negative stoichiometric coefficient, SBO:0000014 “enzyme” used as a participant role, a locally minted ChEBI twin sitting alongside the correct anchor — and assert that validation fails. A validator nobody has seen reject anything is not known to work. (That PLP is never a reaction participant is asserted separately, as a competency-question test rather than a shape.)

5. Competency questions: specification and test suite at once

Competency questions are the standard method for specifying an ontology (Grüninger & Fox 1995; NeOn): before building, write the questions it must answer. They are the requirements document.

Here they are also executable. Each carries the natural-language question, the SPARQL, and the expected answer — so the requirements are the regression suite. A question that stops being answerable breaks the build.

Why this specific choice lands

CQ01–CQ04 are quoted verbatim from NFDI4Cat's own biocatalysis competency questions — the set Mark Dörr wrote himself and committed to nfdi4cat/ontology-development on 9 April 2024.

So the test suite is not invented questions that happen to pass. It is his own contribution to the consortium, returned in working form. Say the words "competency questions" in the presentation.

CQ10 and CQ11 — the two that exist because a test suite lied

There are eleven competency questions, not nine. The last two are the best evidence in the repository, and they exist because of something that was measured rather than suspected.

Every identifier link was repointed to a nonexistent CHEBI_99999999. The result: 9 of 9 questions still passed, SHACL still conformed, and the test asserting the link is a URIRef was still green. Nothing noticed.

The reason is the pattern this project keeps finding in itself: the oracle and the subject came from the same row. Every question projected a label, and the label and the identifier are two fields of one reference_data entry. Corrupt the identifier and the label still matches.

CQ10 and CQ11 project the PURL itself, and a regression test corrupts the graph and asserts the suite notices. The line to say: "For a while I couldn't tell a right identifier from a wrong one, and I measured it." That is worth more than any claim of care.

The half that cannot be answered is the better half

His set is enzyme-centric — production, purification, characterisation, kinetics, immobilisation, engineering. A three-reaction graph answers a well-defined minority. The rest is recorded explicitly in OUT_OF_SCOPE_QUESTIONS:

Cannot answerWhat that would need
KM, kcat, catalytic efficiency quantities with units — where QUDT vs OM-2 vs EMMO stops being academic
which organism produces enzyme X the federation (which works) or an organism model
purification, immobilisation, engineering a model of laboratory processes — i.e. LARA's actual domain
Why volunteer the limitations?

Because the assessor published a paper in November 2025 titled "Limits and solutions for ontological representation of chemical reactions". He catalogued where this gets hard.

Presenting a toy model as though it were general invites him to find the edges himself. Presenting the edges yourself, with what each would require to cross, is the same conversation with you leading it.

6. What to be able to say

The 30-second version

"OWL and SHACL do different jobs — inference under an open world, validation under a closed one — so both are here. The demonstrating case is a cardinality of one with two licences asserted: an OWL reasoner infers the two licences are the same thing, SHACL reports a violation. The shapes are hand-written with a message on every constraint and run with metashacl so a typo fails loudly. And the competency questions are the test suite — CQ01–CQ04 quoted verbatim from NFDI4Cat's own set, with the ones this model cannot answer recorded alongside what each would require."
