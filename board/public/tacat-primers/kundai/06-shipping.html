Chapter 6

Shipping it

Docker and CI look like plumbing. They are the part that turns a claim into evidence — and one of them was the single biggest defect in the first submission.

★★ good to know 14 min Docker · CI · uv one open item

1. The problem being solved

"It works on my machine" is a joke in software because it is the default state. A program depends on a specific Python version, twenty libraries each at a specific version, system tools like a Java runtime, files in particular places. Change one and it may break — or worse, work differently.

You already know this

A protocol that works in your hands and nowhere else is not a result. The reagent lot, the supplier, the incubator, the water — all of it is part of the method whether or not you wrote it down. Reproducibility means someone else, somewhere else, gets your answer.

Everything in this chapter is the software version of writing down the complete method.

2. uv and the lock file

uv manages the project's Python dependencies. It was named in the assignment, and it is what the assessor uses in his own published packages.

pyproject.toml — the catalogue number

What the project needs, loosely: "rdflib version 7 or newer". Enough to order the right thing.

uv.lock — the lot number

What it was actually built with: rdflib 7.6.0 and every transitive dependency, pinned, with checksums. Enough to reproduce the exact experiment.

Same catalogue number, different lot, different result is a real phenomenon in both worlds. The lock file is committed for exactly that reason.

3. Containers

A container packages the application together with its entire environment — interpreter, libraries, system tools, data files — into one artefact that runs much more reproducibly on any compatible host. Not identically anywhere: it still depends on a compatible CPU architecture and kernel, and on base-image tags being pinned by digest rather than by a name someone can move.

4. The build has two stages, and the seam is the point

HermiT is a Java program, so reasoning needs a Java runtime. But the service does not reason — it answers queries from an already-reasoned graph. So why would the shipped image contain Java?

It does not. Press build.

You already know this

Do the messy prep in the prep room; carry only the purified product into the clean room. The solvents, the column and the rotavap stay behind — they were needed to make the thing, not to use it.

Two smaller details worth being able to explain:

  • The container runs as an unprivileged user, not root — if the service is ever compromised, the attacker inherits an account that owns almost nothing.
  • HEALTHCHECK makes the container test itself on a schedule using /health, so a hung service is marked unhealthy rather than silently accepting connections and answering none.
Do not overstate what a health check does

A Docker HEALTHCHECK sets a status — starting, healthy, unhealthy. It does not restart anything by itself. Acting on that status is the job of a restart policy, a Compose dependency, or an orchestrator.

Worth getting right because it is the kind of small overclaim an experienced reviewer notices, and the accurate version is no harder to say: “the check marks the container unhealthy; something above it has to act on that.”

A one-word bug worth knowing about

An earlier version ran uv run tacat build in the builder. A bare uv run re-synchronises the environment with the default dependency groups — silently reinstating the dev group excluded three lines earlier. Result: pytest, ruff, mypy and bandit were all copied into the shipped image.

The fix is uv run --no-dev. Nothing failed; the image was just quietly wrong.

5. CI/CD — and why step 5 was blocking

CI means: a server, not your laptop, rebuilds the project from scratch on every change and runs every check. If anything fails, the change is rejected.

You already know this

Automated QC on every batch, run by the facility rather than the person who made the batch, with release criteria fixed in advance. The value is not that it catches mistakes you know about — it is that it is independent of you. A check you run when you remember is not a control.

Note what that asserts: not merely that the reasoner ran, but that it produced exactly the expected result. A defined class that classifies nothing would pass an ordinary consistency check in silence. This is the difference between a gate and a decoration.

Why the image is tagged by commit

Images get a tag like :latest — but latest moves. Pulling it today and next month may give different software with no way to tell. So the image is also tagged with the exact commit it was built from. A tag that moves is not a reproducible reference — the same reason you cite a DOI rather than "the current version of the page".

6. Why this was the biggest defect in v0

v0 — written

A well-written .gitlab-ci.yml that had never run and could not: the project lived on GitHub inside an unrelated repository. No pipeline, no image, nothing to pull.

now — evidenced

A green pipeline on a real GitLab instance, with an image in the registry tagged by commit, and the badge linked from the README.

Four of five required steps were evidenced. The fifth was written. Those are not the same, and the gap is the whole point of the step: a CI file that has never executed proves nothing. A green pipeline is the only thing in the submission that demonstrates the project builds somewhere other than the author's laptop.

The gate that proves the whole layer

Building the graph twice produces byte-identical output, and a CI job now checks it on every commit. The chain Owlready2 → HermiT → rdflib serialisation is exactly where a change in set-iteration order could make output vary, and the failure is invisible: the graph stays correct while quietly ceasing to be reproducible — which is the claim this entire container and CI layer exists to support.

The reproducible-build job builds twice and compares the bytes; tests/test_reproducibility.py asserts the same thing. If asked "how do you know it is reproducible?" the answer is now "the pipeline fails if it is not" — which is a different kind of answer from "I checked."

Byte equality, not just isomorphism. Two graphs can carry identical triples in a different order — logically the same, different bytes. A registry tag and a source checksum depend on the bytes, so that is the property gated; the suite checks the weaker semantic form too.

7. What to be able to say

The 30-second version

"The reasoner runs at image-build time, not at request time. The builder stage installs a JVM, runs HermiT once and writes the reasoned graph; the runtime stage copies that artefact and installs no Java at all — so the container starts with the graph already loaded, needs no network, and answers an inferred type from plain SPARQL. If reasoning fails, the image does not build. CI runs code gates, then data gates — including an assertion that the inference actually fires — and only then builds the image, tagged by commit SHA because a tag that moves is not a reproducible reference."
