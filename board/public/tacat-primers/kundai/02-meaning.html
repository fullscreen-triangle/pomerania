1. What an "ontology" actually is

The word sounds philosophical. In practice it is a vocabulary with rules a machine can compute over. Three levels:

LevelGives youExample
A vocabularyAgreed names. No rules. "we all call it hasParticipant"
A schema (RDFS)Names + hierarchy + simple typing. "every Cofactor is a ChemicalEntity"
An ontology (OWL) Plus logical statements a reasoner can draw conclusions from. "anything with these four features is a transamination"

The jump to the third row is where this project lives, and it is the difference between describing your data and deriving facts about it.

2. Classes and individuals

You already know this

"Alanine transaminase" as a classification — an EC entry, a catalytic activity you can look up — is a class. It has no concentration and no location.

The purified protein in the tube in your −80 is an individual. It has a concentration, it was purified on a Tuesday, and it belongs to that class.

Species vs specimen. Ontologists call the class layer the T-Box and the individual layer the A-Box.

classes here

BiochemicalReaction · ChemicalEntity · AminoAcid · TwoOxoAcid · Enzyme · ReactionParticipant · TransaminationReaction

individuals here

REACT_0000002 (the specific ALT reaction) · CHEBI_29985 (L-glutamate) · EC_2_6_1_2 · PART_0000002_01

Note AminoAcid and TwoOxoAcid are classes, and every chemical individual is assigned to one when the graph is built. That assignment is what the reasoner uses in §6 — it is doing real work, not decorating.

3. Why a triple cannot hold a participant

The obvious model is a property per role — and it was what v0 did:

Now express 2 H₂O. Where does the coefficient go? A triple has three slots and all three are occupied. There is nowhere to put a fourth piece of information about that particular participation.

You could invent hasSubstrateWithCoefficient2 — then one property per possible coefficient, none comparable to the others. This is not a stylistic problem; it is a hard limit of a three-slot statement.

You already know this

It is a join table — what any relational database uses for a many-to-many relationship with extra columns. It is also what both major biochemistry standards do: BioPAX calls it Stoichiometry (its own documentation says "n-ary bridge"), SBML calls it SpeciesReference. W3C published it as a recommended pattern.

They might ask: NFDI4Cat's own Reac4Cat does this differently

True, and knowing it is the point. Reac4Cat uses a BFO-style role pattern with educt-mixture and product-component-set groupings, not an n-ary node with a coefficient.

The answer: "I used the W3C n-ary pattern because it carries stoichiometry, which the role pattern does not; I know Reac4Cat took the role route, and if the requirement were alignment with their upper-ontology commitments rather than inspectable coefficients, I would switch."

4. Necessary vs sufficient — the core idea

The single most important concept here. It is not a computing idea at all; it is a logic idea you already use.

You already know this

"All serine proteases have a Ser–His–Asp catalytic triad."
A necessary condition. It lets you check a known serine protease. It does not let you look at an unknown protein and conclude anything.

"Any hydrolase with that triad, arranged like this, attacking a peptide bond, is a serine protease."
Necessary and sufficient. Now it works both ways — take an unclassified protein, check the conditions, derive the classification.

Membership is computed from the structure of the data.

A transamination reaction is any biochemical reaction that —
consumes an amino acid, and consumes a 2-oxo acid, and
produces a 2-oxo acid, and produces an amino acid.

That is the net-reaction pattern of a transamination, written as logic. The amino group moves from donor to acceptor, so each class appears on both sides in opposite roles. .some(...) means "has at least one participant such that…".

5. Try it

The four switches below are the four conjuncts. Nothing here is a lookup table — the verdict is computed the same way HermiT computes it.

Why it is written over classes and roles, never molecules

The definition never mentions L-alanine, or 2-oxoglutarate, or any ChEBI identifier. Only AminoAcid, TwoOxoAcid, Reactant, Product.

Written as "has CHEBI_57972 as a reactant", it would classify exactly the three reactions it was reverse-engineered from — an enumeration wearing a definition's clothes. Written over classes, it generalises to transaminations the model has never seen. This is the sentence to say in the presentation.

6. What a reasoner actually does

A reasoner reads logical statements and works out everything else that must be true. This project uses HermiT, driven from Python by Owlready2. HermiT is written in Java — which is why the build needs a JVM, a detail that matters in Chapter 6.

A fair analogy, and its limit

It resembles submitting an uncharacterised sequence and getting a family assignment back. But BLAST answers by similarity — statistical, and it can be wrong. A reasoner answers by deduction: if the premises hold, the conclusion is guaranteed. It cannot be a bit right.

Where the reasoner's premises come from — and it is a fair question

HermiT concluded that three reactions are transaminations because their participants are AminoAcid and TwoOxoAcid. So: how does it know 2-oxoglutarate is a 2-oxo acid?

Because a person put it in a list. population.py types each entity by membership of TWO_OXO_ACIDS or AMINO_ACIDS in reference_data.py. There is no owl:imports of ChEBI. The premises are hand-asserted, and they are exactly the two predicates the conclusion tests.

The answer: "They come from a curated list, not from ChEBI — so the inference is one assertion removed from its premises. Importing ChEBI would fix it and would also pull forty thousand classes into a three-reaction demo; the honest middle is a SHACL check that the asserted type agrees with ChEBI's own hierarchy, fetched at build time."

7. The open-world assumption

You already know this

You did not assay for catalase, so you have no catalase result. That is not a negative result, and you would never write "this strain lacks catalase" on that basis. Absence of evidence is not evidence of absence — the open-world assumption is that instinct, formalised.

Precision matters here — an expert will probe it

HermiT did not prove glutamate dehydrogenase is not a transamination. It failed to derive that it is one. Under an open world those are different statements.

The code computes the excluded set as a subtraction, which is a closed-world reading of an open-world result. Say it precisely: "HermiT did not derive it, because the roles are wrong" — not "HermiT proved it isn't one."

8. The negative control

You need no explanation of why a control matters. What is worth knowing is why this one is well chosen.

A defined class recognising exactly the three things you built it for proves nothing — you could have written "a transamination is one of these three" for identical output. The control is what distinguishes a definition from a list.

The three transaminationsThe control (GDH), as shipped
participants modelled42
L-glutamate — an AminoAcidproductreactant
2-oxoglutarate — a TwoOxoAcidreactantproduct

It contains both headline molecules — the two you would name if asked what these reactions are about — with their roles reversed. It is not derived. Any definition keyed on which molecules are present would have swallowed it whole.

Say this before he constructs it — the shipped control is weaker than it looks

Only two of glutamate dehydrogenase's six species are modelled: L-glutamate in, 2-oxoglutarate out. The redox cofactors were left out. With two participants it cannot fill four role-slots, so the reasoner excludes it on arity — before role is ever consulted.

The role discrimination is real; this control does not demonstrate it. A four-participant reaction with the roles reversed is refused — that is the control it should have been. Concede the difference yourself: "my control fails on the count before the roles matter, and I would replace it with the four-participant one."

Scroll back to the classifier, load the control, and flip the two red switches — a real non-transaminase becomes one the moment its roles change.

9. Why the reasoning happens at build time

Reasoning is slow and needs Java. So it runs once, when the container image is built, and the conclusions are written into the data file.

That is why data/reactions.ttl contains a tacat:TransaminationReaction even though nothing asserted it. The running service answers "which reactions are transaminations?" by plain lookup, with no reasoner and no JVM anywhere near it.

A detail worth knowing, because it nearly went wrong

Owlready2 files reasoner output into a separate internal ontology. The natural call — onto.save() — would have written a perfectly valid file with none of the inferred types in it. The graph would have looked fine and the entire inference would have silently evaporated. The code serialises the whole world instead.

Same silent-failure pattern as Chapter 1's string-vs-IRI bug, different costume.

10. What to be able to say

The 30-second version

"TransaminationReaction is a defined class — necessary and sufficient conditions — expressed over chemical classes and participant roles rather than over specific molecules. No reaction is ever asserted to be one; HermiT derives all three at build time. And there is a negative control: glutamate dehydrogenase contains both headline molecules with the roles reversed, and is correctly not derived, because the definition discriminates on role rather than on molecular presence."
